# 记忆卫生 · 冷热分层自查

> **环境**：DSH + `dsh-core-memory` 插件；路径按 `~/.dsh` 写，Obsidian vault 路径请换成你自己的。已在 DSH 0.2.1-rc.2 / Node 24 上测试。

## 一、层级与预算

| 层 | 载体 | 预算 / 限制 | 放什么 |
|---|---|---|---|
| 热 | `~/.dsh/memory/MEMORY.md` | ≤2500 字符（预算），3000 字符（插件截断上限），留 500 缓冲 | 每轮都该遵守的规则、触发词路由、环境路径、边界 |
| 温 | `~/.dsh/memory/notes/` + `index.json` | 不设硬上限 | 带日期的事实、一次性结论、待查细节、历史决策 |
| 冷 | Obsidian 笔记（`知识库/` 优先） | 不设硬上限 | 命令/参数/步骤类手册、可复查的长流程 |

**字符口径（重要）**：插件 `lib/index.js` 用 `core.length`（JS 字符 / UTF-16 码元）判断 >3000 截断；`memory_core` 的返回文案却写「字节」。**本 skill 一律按字符判定**，不要被「N 字节」文案带偏。字节数只作参考。

## 二、判定表

### 上升（温/冷 → 热）三条

1. **被用户纠正过的错**：已经沉淀成稳定规则、且每轮都该遵守的，规则化后进热层。
2. **每轮必备**：触发词路由、环境路径、边界、硬性流程。
3. **超过三行的一律只进温层**：长解释、长步骤不进 `MEMORY.md`。

### 下降（热 → 温/冷）三条

1. **核心 >2500 字符**：把「最不常触发」的降为归档，并在热层留一行指针。
2. **带日期且 30 天未引用的细节**：归档（注意：插件没有引用次数统计，「未引用」只能人工判断）。
3. **命令/参数/步骤类细则**：下沉知识库笔记，热层留路径。

> 降级 ≠ 删除。先把内容 `memory_write` 成归档，确认写成功，再精简热层；删除只在用户明确要求时用。

## 三、触发时机

- 用户说「记忆精简 / 整理记忆 / 记忆体检」→ 直接按本 skill 跑。
- 每周固定时间 → 跑本周自查。
- 每次 `memory_core` 操作返回「当前 N 字节」→ 看数字，**N > 2500 当场提示并走降级流程**（注意这是字符数，不是字节）。

## 四、执行流程

1. **跑脚本（只读）**
   ```bash
   node ~/.dsh/tools/memory-stats.mjs
   ```
   需要机器可读时加 `--json`。脚本输出：热层总分节字符数、归档条目数、索引一致性、按判定表的升降候选。
2. **核数**：把脚本数字与 `MEMORY.md` 实际内容对一遍；有异常（索引缺失、路径错误）先报，不擅自修。
3. **出建议清单**：逐条写「动作 / 对象 / 判定表依据 / 建议落点 / 风险」，**只出清单，不改文件**。
4. **等用户确认**：结束回合，等「按 1、3 执行」这类明确指令。用户没确认就不动 `MEMORY.md`、不动归档、不动笔记。
5. **执行（确认后）**：
   - 降到温层：`memory_write` 新建归档（标题带日期与来源）→ 成功后再用 `memory_core` 的 `replace`/`remove` 精简热层 → 热层留一行指针。
   - 降到冷层：`obsidian_write` 写进 vault 的知识库 → 热层留路径。
   - 上升：`memory_read` 取归档全文 → 压成 ≤3 行规则 → `memory_core` `append` 到对应分节。
   - 删除：只有用户明确说删，才 `memory_delete`（会留墓碑）。
6. **复核**：改完再跑一次 `memory-stats.mjs`，在回复里给「改动前 → 改动后」字符数对照。
7. **留痕**：重大调整写一条归档记忆（`memory_write`，标签含「记忆分层」），说明改了什么、为什么。

## 五、输出格式

```
## 记忆体检 · YYYY-MM-DD

【事实】热层 1234 字符（预算 2500 / 上限 3000），归档索引 42 条。
【推断】按判定表③，L16 的命令/参数适合下沉知识库，热层留路径。
【猜测】「环境」第 3 条可能不常触发——没有引用数据，需你判断。

### 建议清单
| # | 动作 | 对象 | 判定表依据 | 建议落点 | 风险 |
|---|---|---|---|---|---|
| 1 | 下沉 | L16 命令/参数 | 下降③ | 知识库/速查 | 低 |

### 请你确认
回复「按 1 执行」或「只做 1、3」；没有确认我不会改文件。
```

- 数字必须标【事实】并给出来源（脚本 / 文件行号）。
- 迁移建议标【推断】，写清依据的判定表条目。
- 「最不常触发」「30 天未引用」这类没有数据支撑的判断标【猜测】，不要伪装成事实。

## 六、边界

- 不改 `AGENTS.md`、不装插件、不手工拼接 `index.json`。
- 不整篇重写 `MEMORY.md`；用分节级 `replace`，保留触发词路由与环境路径。
- 一次只处理用户确认过的条目；批量重排先另出清单。
- 归档索引与文件不一致时，只报告并给修复方案，等确认后再动 `index.json`。
